WHAT THIS PROVES
  updateAppointmentStatus() passes the whole request body to findByIdAndUpdate().
  Nothing limits it to the status field, and nothing checks that the appointment
  belongs to the doctor making the request — so a doctor can even reassign it.

METHOD: black box — a doctor edits another doctor's appointment, adding extra fields
  caller      : alpha (Doctor, id 6ab8bda06c302a5700392ed8)
  appointment : 6ab8bda06c302a57003930d5  — patient Alice, booked with Dr Beta (id 6ab8bda06c302a5700392edb)
  seeded values: patientFirstName "Alice", appointmentCharges "3000", city "Kandy",
                 department "Oncology", status "Pending", doctor = Dr Beta

ATTACK 1 — send fields other than status (mass assignment)
> fetch PUT $BASE/api/v1/appointment/update/6ab8bda06c302a57003930d5 [with alpha's session cookie]
  body: {"status":"Accepted","appointmentCharges":"1","city":"HACKED","department":"HACKED-DEPT","patientFirstName":"Overwritten"}
  HTTP 404
  {"success":false,"message":"Appointment not found"}
  RESULT: ✅ update refused (HTTP 404) — a doctor cannot edit another doctor's appointment

ATTACK 2 — reassign the owner: set doctor = Dr Alpha, stealing Dr Beta's appointment
> fetch PUT $BASE/api/v1/appointment/update/6ab8bda06c302a57003930d5 [with alpha's session cookie]
  body: {"doctor":"6ab8bda06c302a5700392ed8"}
  HTTP 400
  {"success":false,"message":"status must be one of: Pending, Accepted, Rejected"}
  RESULT: ✅ owner not reassigned (HTTP 400) — the doctor field is ignored and a foreign doctor is refused

CONTROL — a patient (Dana) tries to update the appointment (role guard that exists)
> fetch PUT $BASE/api/v1/appointment/update/6ab8bda06c302a57003930d5 [with dana's session cookie]
  HTTP 401
  {"success":false,"message":"Unauthorized - No token provided"}
  RESULT: ✅ patient blocked (HTTP 401) — the role check works; the MISSING checks are field-scoping and ownership
